## 4. Шви між кроками

1. **В1 (дефект):** `applySetting` скасовує `pending` огляди **без перевірки оренди** (`src/db/settings.ts:182`), хоча в тій самій функції корені планувальника перевірку мають (`:149`, `lease_until IS NULL OR lease_until <= now`). Відправка закриває `WHERE status = 'pending'` (`src/db/digests.ts:166`) → 0 змін, відправлений огляд лишається `cancelled` без `sent_at`, `lastSentFireAt` його не бачить → межа доби не діє → новий рядок `applySetting` на сьогодні 10:00 іде. Те саме для `tz` і `weekly_dow`. Вікно — тривалість `sendMessage`, раз на добу, але шов 3.1 × 3.2 рівно там, де фаза обіцяє «не дублює».
2. Дві копії вставки рядка огляду: `insertStatement` (`db/digests.ts:136`, не експортований) і той самий SQL у `db/settings.ts:185`. Змінять форму — розійдуться. → «Борг».
3. Мертва константа `ALL_LIMIT` (`digests/schedule.ts:11`, ніде не читається); стелю «показати все» насправді тримає `OPEN_LIMIT` (`db/digests.ts:11`). → «Борг».
4. Третя копія `hhmm`/`pad` (`digests/schedule.ts:40-41`; уже є `reminders/plan.ts:48-49`, `reminders/render.ts:36-37` — R-2 Д1), літерал `86_400_000` у `digests/dispatch.ts:74` поруч із `DAY_MS` у `schedule.ts`. Чотири форми тих самих полів користувача: `DigestSettings`, `Settings` (`db/settings.ts`), `DigestUser`, `MissingDigest`. → «Борг».
5. Неузгодженостей назв `kind`/callback немає: `dg:all`, `wk:t|s|r:<id>`, `st:*` не перетинаються; `isDigestCallback`/`isSettingsCallback` перевіряються до загальних кнопок нагадувань.
