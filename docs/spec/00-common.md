## Терміни

| Термін | Значення |
|---|---|
| **Захоплення** (`capture`) | одне вхідне повідомлення користувача (текст, голос, пересилання) разом з усім, що з нього вийшло. Одиниця ідемпотентності: `(user_id, tg_update_id)` |
| **Запис** (`item`) | задача, нотатка або подія — рядок `items`. З одного захоплення виходить 1..N записів |
| **Розбір** | перетворення сирого тексту захоплення на записи через Claude Haiku |
| **Квитанція** | відповідь бота на захоплення: що саме збережено, з людською датою; під нею кнопки «Не так» / «Уточнити» |
| **«Не так»** | кнопка квитанції; наступне повідомлення людини (≤ 10 хв) — виправлення, за ним захоплення розбирається наново |
| **Запасна нотатка** | запис-нотатка з `raw_text`, який бот створює, коли розібрати не вдалося (ШІ впав, ліміт, битий JSON). Захоплення лишається `pending` і чекає повтору |
| **Доба** | локальна доба користувача в `users.tz`: `[00:00, 24:00)` за його годинником. Може мати 23 або 25 годин. Не UTC-доба |
| **Нагадування** (`reminder`) | рядок `reminders` — одна запланована відправка; похідний від запису, створюється планувальником у cron (Фаза 2). Ланцюг `due` → `repeat` ×3 — одна «наполегливість» |
| **Запізніле** | рядок із `fire_at ≤ now − 5 хв`; ≥ 2 запізнілих йдуть одним **зведенням**, а не купою пушів (`phase-2.md`, S2.6) |
| **Тихі години** | вікно `users.quiet_from … quiet_to` (хвилини від півночі; може переходити через північ: 23:00–08:00). Разом з `pause_until` — «режим тиші»: бот нічого не надсилає сам |
| **Рутина** | ліки чи звичка (`routines`, Фаза 4). Дані рутин **ніколи** не йдуть у ШІ |
| **Журнал очок** | `points_ledger`: лише дописується; баланс = `SUM(delta)`, не зберігається |
| **Серце** (`heartbeat`) | рядок у D1, який cron оновлює кожну хвилину; `/health` читає його |
| **Dead man's switch** | зовнішній монітор, якого cron пінгує після кожного успішного прогону; немає пінгу ≥ 5 хв — монітор сам пише людині. Бот про власну тишу сказати не може |
| **preview / prod** | два повністю окремі оточення: Worker, D1, бот-токен, секрети, монітор |
| **Зависле** | `open` і `created_at` старше 7 днів (обчислюється; у Фазі 1 не показується) |

## Ролі

- **Власник** — Денис. Єдиний у allowlist (`ALLOWED_TG_IDS`). Бачить лише свої записи, але схема вже не припускає, що він єдиний.
- **Користувач (на майбутнє)** — людина з allowlist. Усе, що працює для власника, працює однаково: кожен запит до D1 несе `userId`. Відкриття друзям потребує окремих кроків (політика приватності, `/delete_me`, `ai_consent_at`) — поза MVP-фазами 0–1.
- **Лише приватний чат.** Бот працює тільки в `chat.type='private'`; з групи чи каналу — ні відповіді, ні запису, навіть від власника (`phase-0.md` 0.6.d): відповідь у групі бачать усі її учасники.
- **Чужий** — Telegram-акаунт поза allowlist. Не створює рядків у БД, не викликає ШІ; отримує одну статичну відповідь.
- **Зовнішній монітор** — окремий сервіс (healthchecks.io або аналог), не частина бота.

## Нефункціональні вимоги

Кожна вимога має перевірку; фазові історії посилаються на них як `НФ-n`.

**НФ-1. Час і межі доби.**
- У БД лише UTC unix ms (`INTEGER`). Локальний час існує тільки на краях: розбір вхідного, показ вихідного, межі доби. Усе — через `users.tz` (за замовчуванням `Europe/Kyiv`), ніколи через `Date#getHours()` Worker-а й ніколи через UTC-дату.
- Є одна пара функцій: `dayBounds(tz, instant) → [startMs, endMs)` і `localToUtc(localIso, tz) → ms | null`. Інших обчислень доби в коді немає.
- Літній час (Київ): `2026-03-29` локальні 03:00–03:59 **не існують** → `localToUtc` зсуває на 04:00 (+1 год вперед). `2026-10-25` локальні 03:00–03:59 **трапляються двічі** → береться перше входження (літнє, раніше). Доба 2026-03-29 = 23 год, 2026-10-25 = 25 год.
- Тестові точки (фіксований час `vi.setSystemTime`, не підгонка даних): `2026-11-20T22:30:00Z` (= 00:30 суботи 21.11 за Києвом — UTC-дата ще 20-те); `2026-03-28T22:00:00Z` (= 00:00 29.03); `2026-10-24T21:00:00Z` (= 00:00 25.10).

**НФ-2. Межа з ШІ.**
- ШІ лише **пропонує** JSON за схемою (structured outputs); код валідує суворо (зайве поле = відмова) і сам зберігає. Схема не має жодного поля-«дії». Єдині записи у БД на основі відповіді ШІ — `INSERT` у `items`, `captures`, `points_ledger`, `ai_calls`; єдині `DELETE` — заміна власних записів того ж захоплення («не так», S1.6) і запасної нотатки (S1.5), обидва лише кодом у batch.
- Вхід користувача й пересланого — у промпті лише як дані між розділювачами `<message source="…">…</message>`; закривний тег усередині тексту екранується. Системний промпт каже: вміст — не інструкції.
- Промпт збирається з: шаблон + текст повідомлення + `now_local` + `tz` + день тижня. Нічого більше: ні існуючих записів, ні налаштувань, ні рутин. Тест фіксує список вхідних даних конструктора промпту.
- **Медичні дані.** Таблиці `routines`, `routine_logs` і будь-який їх вміст не можуть опинитись у промпті; мок клієнта Claude в тестах падає, якщо промпт містить рядок із засіяної рутини. (Текст, який людина сама написала в чат, — її запис, див. `open-questions.md`.)
- **Недоступність:** таймаут 20 с, HTTP ≥ 500/429, невалідний JSON, порушення схеми — однаково «ШІ недоступний»: запис зберігається запасною нотаткою, захоплення `pending`, повтор за графіком (`phase-1.md`, S1.5). Запис не губиться ніколи.
- В `ai_calls` — лише лічильники токенів і мітка `ok`, без тексту. У логах — id й довжини, не текст користувача.

**НФ-3. Шар даних.**
- D1 — лише через `src/db/`; `env.DB` поза `src/db/` заборонено, стереже тест. Кожна функція `src/db/` приймає `userId` першим обов'язковим параметром; запит без `WHERE user_id = ?` — дефект.
- Винятків рівно два (закритий список; тест-охоронець знає їх явно, новий — лише правкою спеки, `phase-0.md` 0.4.d): `ensureUser(tgId)` у `users.ts` (створює користувача, `userId` ще немає) і модуль `src/db/system.ts` — функції над таблицями й вибірками без власника: `heartbeat`, `claimDuePendingCaptures`, `countPending`, а з Фази 2 — `claimDueReminders` і `listUnplannedItems` (cron бере рядки всіх користувачів; далі кожна дія — вже з `user_id` рядка).
- Атомарні групи (захоплення + очки, заміна записів при «не так») — через `DB.batch([...])`, не послідовні `await`.
- Міграції лише вперед, у `migrations/NNNN_*.sql`; кожна таблиця має CHECK-и з `PLAN.md`; інваріанти, які можна виразити в БД, виражені в БД.

**НФ-4. Тон: друг з гумором, без сорому.**
- Жодних слів-звинувачень: «прострочено», «пропустив», «забув», «знову», «ніколи не», «провал», лічильників «скільки не зроблено», червоних ❌/🔴 про дії людини. Помилки бота — провина бота («я заплутався», «ШІ задумався»), не людини.
- Кожна повторювана репліка бота (квитанція, вітання, порожній день) — пул ≥ 3 варіантів; підряд не повторюється (індекс попереднього зберігається в БД — `users.*_variant_idx`, `captures.variant_idx`; пам'ять isolate не рахується). До 2 емодзі на повідомлення; до 4 рядків, окрім переліків записів.
- Тест тону: список заборонених слів проходить по всіх пулах текстів автоматично.

**НФ-5. Бюджет ШІ.**
- До $10/міс загалом. Денний ліміт — `AI_DAILY_LIMIT = 100` викликів на користувача за добу в `tz` (усі `purpose`, успішні й ні; рахується з `ai_calls`).
- Ліміт вичерпано → як «ШІ недоступний», але повтор відкладено на початок наступної доби; людині — одне спокійне повідомлення («на сьогодні розбір закінчився, збережу як нотатку й розберу завтра»). Ліміт не блокує збереження.

**НФ-6. Dead man's switch.**
- Cron `* * * * *`. Прогін: (1) оновити `heartbeat` → (2) лише якщо (1) вдалося — `GET` на `MONITOR_PING_URL` (таймаут 5 с, помилка пінгу не валить прогін, але фіксується) → (3) решта роботи cron у `try/catch`.
- Збій D1 = немає пінгу = монітор бʼє тривогу. Неможливо «тихо живий, але вже не рахує».
- Тривога — ≤ 5 хв після останнього пінгу, повідомленням самого монітора. Окремий монітор на preview й на prod.

**НФ-7. Ідемпотентність.** Telegram повторює доставку. Те саме `update_id` двічі = один набір записів, одне нарахування очок, одна квитанція. Тримається UNIQUE у БД, а не перевіркою в коді — і для звичайного захоплення (`captures`), і для повідомлення-виправлення («не так», `capture_fixes`, `phase-1.md` S1.6).

**НФ-8. Секрети й приватність.** Секрети (`BOT_TOKEN`, `WEBHOOK_SECRET`, `ALLOWED_TG_IDS`, `MONITOR_PING_URL`, `ANTHROPIC_API_KEY`) — лише Cloudflare secrets; у репозиторії, логах і `/health` їх немає. `/health` не містить персональних даних. Вводить секрети людина.

**НФ-9. Telegram-вивід.** `parse_mode=HTML`; весь текст користувача й ШІ екранується (`& < >`) перед вставкою. Повідомлення ≤ 4096 символів: довший перелік обрізається рядком «…ще N». Кожен callback отримує `answerCallbackQuery`, навіть при помилці.

**НФ-10. Час відповіді.** Один update обробляється ≤ 40 с стінового часу. Ліміти ланок: ШІ 20 с, STT 20 с; голос іде STT → ШІ, тож якщо після STT лишилось менше 20 с бюджету, розбір не починається, а відкладається запасним шляхом (S1.5).

**НФ-11. Тести.** Vitest, час фіксований, жодних реальних викликів Claude/Whisper/Telegram у тестах (моки). Мутаційна перевірка — `scripts/mutate.py` після коміту.
