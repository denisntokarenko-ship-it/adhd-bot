# Рішення

Append-only: рядки лише дописуються. Скасоване рішення лишається з позначкою «Скасовано РРРР-ММ-ДД на користь …» — інакше наступна сесія переухвалює те саме.
Рішення плану (опитування 2026-11-20) — у таблиці «Ухвалені рішення» `docs/PLAN.md`; тут — рішення, ухвалені під час специфікації й реалізації.

Формат: `- **[РРРР-ММ-ДД] [рішення]** — [причина, одне речення].`

- **[2026-11-20] Специфікація ріжеться на зрізи `docs/spec/phase-N.md` + `00-common.md`, кожен ≤ 40 КБ** — сесія кроку читає лише свій зріз, бюджет тримає `scripts/check-docs.sh`.
- **[2026-11-20] Доступ лише за allowlist `ALLOWED_TG_IDS` (секрет), порожній список = відхилити всіх** — відкритий бот дозволив би чужим спалювати бюджет ШІ й плодити рядки; «схема під багатьох» не означає «двері відчинені» (`phase-0.md`, S0.6).
- **[2026-11-20] Пінг монітора — лише після успішного запису heartbeat у D1** — інакше cron, що вже не може писати, виглядав би живим; тиша = тривога.
- **[2026-11-20] `/health` — 200 навіть коли cron ще не запускався (`stale:true`), 503 лише при збої D1; `sha` приходить зі змінної деплою** — щойно викочений Worker чекає першого cron до ~15 хв, хибна тривога під час релізу гірша за прапорець.
- **[2026-11-20] Усі часові поля — з injectable `clock`, без SQL `DEFAULT` на час** — тести фіксують час (`setSystemTime`); прямих `Date.now()` поза `clock.ts` немає.
- **[2026-11-20] `users.plan` і `users.ai_consent_at`, `items.person_id` не створюються у Фазах 0–1** — додаються міграціями, коли потрібні; `person_id` посилався б на таблицю, якої ще немає.
- **[2026-11-20] Нова таблиця `captures` (одне вхідне повідомлення) поза `PLAN.md`** — дає ідемпотентність за `update_id` на рівні UNIQUE, «оренду» для повторів і точку відліку для «не так»; без неї очки й записи дублюються при повторі доставки Telegram.
- **[2026-11-20] Очко `capture` — за захоплення (повідомлення), не за запис; частковий унікальний індекс у БД** — не заохочує дроблення, повтор доставки не нараховує вдруге.
- **[2026-11-20] Схема відповіді Haiku має сьомий прапорець `date_unclear`** — без нього код не відрізнить «дати не було» від «дата була, але неоднозначна», а правило «неоднозначне → без дати + уточнення» не виконати. Це не поле «дії».
- **[2026-11-20] Відповідь ШІ валідується суворо: зайве поле, не той тип, невідомий `kind` — відхилення всієї відповіді й запасний шлях; довжини нормалізуються (обрізання), а не відхиляються** — доказ, що «полів-дій» немає, простіший, ніж їх чистка; довгий заголовок не варто втрачати розбір.
- **[2026-11-20] `due_local` — локальний ISO без зсуву; переведення в UTC лише кодом (`localToUtc`): неіснуючий час (літній перехід) зсувається вперед, подвійний — перше входження** — ШІ не знає зсувів; дві детерміновані точки дають тестовані межі.
- **[2026-11-20] «Минуле» = `due_at ≤ now`; для `all_day` — дата < сьогодні в `tz`; далі за 2 роки = неоднозначне** — запис не втрачається, дата не вгадується, людину питають однією короткою фразою.
- **[2026-11-20] «Не так» і повтор розбору замінюють записи (DELETE + INSERT в одному batch) — єдині дозволені видалення в Фазі 1** — це заміна власних записів захоплення за явним натисканням кнопки (правило 3 «видалення лише кнопками» збережене); запасна нотатка — службова.
- **[2026-11-20] Друге «Не так» бере оригінал + найновіше виправлення; вікно виправлення 10 хв** — зберігати ланцюг виправлень для MVP зайве, стан тримає `captures.fix_requested_at` без нових колонок у `users`.
- **[2026-11-20] Повтор розбору: 6 спроб із затримками 5 хв/15 хв/1 год/3 год/6 год, далі `gave_up` без повідомлень; у режимі тиші й при вичерпаному ліміті спроба не витрачається** — запис не губиться, а людина не отримує нічного шуму чи сорому.
- **[2026-11-20] Ім'я автора пересланого повідомлення не йде в ШІ й не зберігається** — мінімізація даних: потрібен лише текст.
- **[2026-11-20] Whisper-виклики не рахуються в `ai_calls` і денний ліміт Claude** — безкоштовна квота Workers AI, не бюджет Claude; їх не обліковують, доки не з'явиться плата.
- **[2026-11-20] `/today` не показує прострочене й не рахує його: лише «сьогодні», «без дати» (до 5) і баланс** — прострочений список — головне джерело сорому (`PLAN.md`, Context); завислі повертаються у вечірньому/тижневому огляді Фази 3.
- **[2026-11-20] `/export` — JSON `version:1` лише власних даних; `ai_calls` і `tg_id` не експортуються** — вихід із системи без прив'язки до Cloudflare; облік вартості й ідентифікатори людині не потрібні.
- **[2026-11-20] `heartbeat` — системна таблиця без `userId`, функції в `src/db/system.ts`, винятком у тесті-охоронці** — правило 1 `CLAUDE.md` не має сенсу для рядка без власника; виняток явний і єдиний. *Уточнено 2026-11-20 (рев'ю 0.2, В4): винятків два, закритий список — див. рядок нижче.*
- **[2026-11-20] Cron-вибірка `pending`-захоплень усіх користувачів — у `src/db/system.ts`** — повтор працює «по всіх», тож `userId` першим параметром неможливий; усі подальші дії над захопленням уже з його `user_id`.
- **[2026-11-20] Номери історій `S<фаза>.<n>`, критеріїв `<n>.<n>.<літера>`** — щоб блок «Перевірка» кожного кроку посилався на них дослівно.
- **[2026-11-20] Рев'ю 0.2, В4: у шарі даних рівно два винятки з `userId` — `ensureUser(tgId)` і `src/db/system.ts` (`heartbeat`, `claimDuePendingCaptures`, `countPending`)** — спека називала виняток «єдиним», а 0.4.d і S1.5.c додавали інші: тест-охоронець за буквою НФ-3 суперечив би спеці.
- **[2026-11-20] Рев'ю 0.2, Б1/Б2: порожній `WEBHOOK_SECRET` = 401 для всіх; бот мовчить у не-приватних чатах** — `undefined === undefined` пропустив би будь-кого, чий `tg_id` знають (він не секрет); відповідь у групі (`/export`) бачать усі учасники.
- **[2026-11-20] Рев'ю 0.2, В2: нова таблиця `capture_fixes` + два тригери — один простір `update_id` для захоплень і виправлень** — виправлення не створює `captures`, тож без неї повтор доставки його update став би «новим захопленням» (подвійні записи й очко); тригери замикають перетин двох UNIQUE, який SQLite не вміє виразити.
- **[2026-11-20] Рев'ю 0.2, В3: `users.greet_variant_idx` і `soon_variant_idx` (Фаза 0)** — «без повтору підряд» потребує сховища, пам'ять isolate між запитами скидається; для квитанцій уже є `captures.variant_idx`.
- **[2026-11-20] Рев'ю 0.2, В5/Д2/Д3: prod без `MONITOR_PING_URL` → `/health` `ok:false,"monitor":"missing"`; `stale = age_ms > 180000`; сміття в `ALLOWED_TG_IDS` → відхилити всіх з 200** — «тихо живий» prod без монітора невидимий; межа в мс не має розходитись з `floor`; 500 змусив би Telegram повторювати update вічно.
- **[2026-11-20] Відхилення від `PLAN.md`: `heartbeat.last_ping_ok_at`** — відрізняє «cron живий, пінг не доходить» від «cron мовчить»; користується `/health` і діагностика 0.3.c.
- **[2026-11-20] Відхилення від `PLAN.md`: `ai_calls.ok`, `ai_calls.error`, `ai_calls.capture_id`** — денний ліміт (НФ-5) рахує всі виклики, а причина збою (`timeout`/`http`/`json`/`schema`) і зв'язок із захопленням потрібні для розбору повторів без тексту користувача.
- **[2026-11-20] Монітор cron — healthchecks.io (безкоштовний Hobbyist), пінг GET на `MONITOR_PING_URL`; period 1 хв + grace 4 хв** — 20 перевірок вистачає на preview+prod, простий GET-пінг; UptimeRobot Free — опитування з інтервалом ≥ 5 хв і без heartbeat-перевірок. Крок 0.5.
- **[2026-11-20] 1.1.g: `wrangler d1 export` падає на базі з віртуальною таблицею FTS5; Time Travel `info` працює, `restore` не перевірено** — живий прогін на D1 preview (`adhd-preview`) з тимчасовою `tmp_fts_review` (видалена; `users`/`heartbeat` не чіпались; міграція `0002` на preview не застосовувалась): контрольний `d1 export` без FTS — успіх; з FTS — `D1 Export error: cannot export databases with virtual tables (like FTS5)`; після `DROP TABLE` експорт знову успішний. Збіг із документацією D1, розд. Known limitations: https://developers.cloudflare.com/d1/best-practices/import-export-data/ (обхід там: видалити віртуальні таблиці → експорт → створити знову). Наслідок: після `0002` повний SQL-експорт prod-бази недоступний; резерв — Time Travel (https://developers.cloudflare.com/d1/reference/time-travel/, обмежень для віртуальних таблиць не вказано) і `/export` у JSON (1.11). `wrangler d1 time-travel info` із FTS-таблицею видав bookmark; `time-travel restore` не виконувався (змінив би `users`/`heartbeat` preview) — **статус: не перевірено — до prod**. Ворота: `0002` на prod лише після закритого 1.1.g, тобто після того, як `restore` перевірено на preview (запис, відкат до bookmark, перевірка `items_fts`). Процедуру «drop FTS → export → recreate» не відпрацьовано: після recreate індекс треба перебудувати (`INSERT INTO items_fts(items_fts) VALUES('rebuild')`) — перевірити, якщо знадобиться.
- **[2026-11-20] Міграція `0002` (1.1) без `points_ledger` і `items.parent_id`** — за промптом 1.1: `points_ledger` — `0003_points.sql` у 1.5, `parent_id` — 5.1 через `ALTER TABLE … ADD COLUMN`; текст `phase-1.md` («Схема») позначено, щоб 1.2 і 1.5 читали одну правду; `captures`/`capture_fixes` у `0002` є (на них FK).
- **[2026-11-20] FTS5-токенайзер `unicode61 remove_diacritics 2 separators 'ʼ'`** — відхилення від рядка спеки: U+02BC (апостроф українських розкладок) для `unicode61` — літера, без `separators` слово «пʼятниця» було одним токеном і не знаходилось за «п'ятниця» (ASCII `'` і `’` — розділювачі); перевірено живцем на preview, захищено тестом «апострофи ', ’ і ʼ взаємозамінні» і мутантом M10.
